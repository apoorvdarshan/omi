## 2. Background
The branch adds an opt-in SwiftUI/Liquid Glass presentation behind the compile flag OMI_IOS_SWIFTUI (Dart const iosSwiftUiEnabled; native only when the flag is on AND Platform.isIOS AND supportsIosSwiftUi()). Flutter screens project their state into versioned snapshots of rows (IosNativeSurface, NativeRow, NativeSection, showIosNativeModal, showOmiSheet nativeBuilder, IosNativeEdit, ...) that a SwiftUI renderer draws; callbacks stay in Dart with the existing owners; any invalid row makes the whole screen fall back to the complete Flutter screen. Read first: app/docs/ios-native-ui.md, app/AGENTS.md, all of app/lib/mobile/native_ui/*.dart, and app/ios/Runner/NativeUI/NativeSurfaceContract.swift (to learn exactly which row kinds/values Swift accepts — you cannot run Swift, so mirror its validation rules carefully). Study migrated screens as idioms: app/lib/pages/settings/usage_native.dart, transcription_native.dart, app/lib/pages/conversations/auto_sync_native.dart, app/lib/pages/conversation_detail/native_conversation_detail.dart, app/lib/pages/settings/people.dart, app/lib/pages/action_items/action_items_page.dart, app/lib/pages/chat/page.dart, and the tests in app/test/mobile/native_ui/ (use test/mobile/native_ui/native_test_host.dart and the debug seams IosNativeSurface.debugNativeHostForTest / nativePresentationEnabled / supportsNativePresentation() so tests reach the native paths on a non-iOS machine). Host tests use app/integration_test/support/native_host_harness.dart (runNativeHostSuite, nativeProjectedRow, nativeHostApp).

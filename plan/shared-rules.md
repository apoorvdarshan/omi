# Cross-batch rules

## Shared file conflicts / frozen files
- The serial primitives phase is the only writer of these shared files, which are frozen for every batch: app/lib/mobile/native_ui/** (ios_native_surface.dart, ios_native_modal.dart, ios_native_home.dart, ios_native_main_navigation.dart, ios_native_settings.dart, ios_native_edit.dart, and the new ios_native_feedback.dart, ios_native_secret.dart, native_graph.dart, native_asset_image.dart), app/lib/ui/feedback/omi_feedback.dart, app/lib/ui/feedback/omi_dialogs.dart, app/lib/ui/components/omi_sheet.dart, all of app/ios/** (Runner/NativeUI/*.swift including the new NativeToastPresenter.swift, NativeListInteractions.swift and NativeGraphView.swift, AppDelegate.swift, Runner.xcodeproj with both targets, Preview.xcodeproj, PreviewApp.swift, PreviewUITests.swift, native_surface_contract_test.swift/.rb), app/test/mobile/native_ui/native_surface_projection_test.dart, app/integration_test/native_ui_host_test.dart and app/integration_test/support/native_host_harness.dart. Every batch is Dart-only. A batch that finds a missing bridge capability must leave that row on the classic fallback and escalate; it must not patch these files.

- l10n: batches must not edit ARB files or the generated app_localizations files. Only three new keys are needed across all batches. The integrator adds them with scripts/l10n.py, translated for every locale, on the primitives head before batches branch, so batch code compiles: dateRangeStart ('Start date') and dateRangeEnd ('End date') for conversation-library-search, and openInMaps ('Open in Maps') for maps-recap. All other copy reuses existing keys (for example edit/done for task reorder, setDueDate for category moves, expand/collapseAction for collapsible headers, copy/copyKey for secrets).

- app/lib/widgets/components/memory_review_card.dart: P0 adds the showMemoryReviewSheet seam with a frozen signature. After that, chat-structured-messages owns the file and adds the native builder, while maps-recap only calls the function from daily_summary_detail_page.dart. If chat merges after maps-recap, the recap sheet simply stays on its classic builder until then.

- app/lib/pages/home/page.dart (tasks-selection-hierarchy) and app/lib/pages/home/native_home_presentation.dart (speaker-review-voice-matches) are separate files of the same Dart library ('part of'). New private identifiers need batch-unique prefixes (_nativeTasks..., _nativeSpeaker...). P2 changes OmiFeedback clearance only in ios_native_main_navigation.dart, never in home/page.dart.

- Frozen cross-batch call signatures (no file overlap, but parallel merges must compile): openConversationListRow (called by frozen ios_native_home.dart), ProcessingConversationPage(conversation:) (library routes to it, live-capture makes it native), DayConversationsPage(date:, fetchConversations:) (recap and search route to it, library makes it native), ConversationMapPage (search routes to it, maps makes it native), CapabilityAppsPage/CategoryAppsPage constructors (chat and summary templates route to them), WalItemDetailPage(wal:) (offline-sync routes to it, recording-detail makes it native), FirmwareUpdate/OmiGlassOtaUpdate constructors (device settings routes to them), InteractiveDeviceOnboardingWrapper, PaymentsPage, UpdateAppPage, AiAppGeneratorPage and MemoryGraphPage(loadGraph:, trackOpenEvent:). Batches may add optional named parameters but must not remove or rename existing ones.

- Shared test infrastructure is read-only for batches: integration_test/visual_audit/fakes.dart, integration_test/journeys/support/hermetic_boot.dart, integration_test/native_ui_inspection.dart, native_advanced_host_cases.dart, native_remaining_host_cases.dart and shared test/ helpers. Each batch writes its own standalone host target, integration_test/native_<batch>_host_test.dart, using runNativeHostSuite, and its own test files. Batch-specific fakes live inside those files. The integrator adds the new host targets to the CI and verification lists.

- Existing default-build tests must stay green without edits: chat_scroll_layout_test, chat_content_block(s)_test, memory_graph_empty_state_test, conversation_map_groups_test, action_items_row_gestures_test, tasks_empty_state_test, speaker_tag_prompt_card_test, feedback_prompt_*/feedback_sheet_intercom_test, goals_widget_performance_test, auto_sync_storage_refresh_test, native_plan_projection_test and the ui_feedback tests. The only existing test reassigned is memory_review_card_test.dart, owned by chat-structured-messages. All extractions (MemoryItem helpers, MemoryReviewController, MessageActionCommands, ChatMessagePlan, MergeActionBar/TaskSelectionActionBar actions, DeviceDiscoveryController, MemoryGraphController, conversation row actions, goals operations) must preserve behaviour, because the default build runs the same code.

- Provider files stay read-only for every batch except app/lib/providers/device_provider.dart, owned by firmware-ota for the firmware prompt and pairing-lost alert. ActionItemsProvider, AddAppProvider, DevApiKeyProvider, McpProvider, MemoriesProvider, ConversationProvider, SyncProvider, PeopleProvider, MessageProvider, GoalsProvider and PaymentMethodProvider are not edited. Batches fence sessions and scope data at the presentation layer, so flag-off behaviour stays identical.

- app/analysis_baseline.json, pubspec.yaml/pubspec.lock, docs/ios-native-ui.md and docs/ios-native-ui-parity.md are integrator-only. Batches add no packages and must not raise analyzer counts. The integrator updates the guide and the parity ledger after merging, including correcting 'Memories list selection' to 'Memories row actions' and 'advanced search result selection' to 'search date filter and People scope', and adding the newly found routes (Goals, reviews list, capability/category apps, app options, DayConversations, live capture/processing, permissions interstitial, freemium and language prompts).

- Temporary sandbox files are owned per batch and must be cleaned in that batch's files: static map PNGs (maps-recap), the AI app icon (app-generator-payouts) and Wrapped share PNGs (existing owner, preferences-shortcuts-wrapped). Delete them on dispose, session change and stale completion. The P0 asset cache (omi_native_assets) holds static bundled artwork shared by the device batches and is never user data.

- Merge order: primitives P0 to P7 land first, serially. All 21 batches branch from the primitives head after the three l10n keys land, and they have no batch-to-batch compile dependencies. Rebase conflicts are limited to the semantic couplings listed above.

## Excluded (stay Flutter)
- PaymentWebViewPage (subscription checkout and customer portal): Dart's NavigationDelegate intercepts the /v1/payments/success and /cancel URLs to resolve the plan flow. SFSafariViewController cannot intercept navigations, and a SwiftUI web primitive would move checkout ownership. The content is already a native WKWebView, and the docs say checkout stays with its existing owner.

- OmiWebPage (Referral program, affiliate.omi.me) and AppHomeWebPage (an app's web home): the content is already a native WKWebView running arbitrary JavaScript. Native chrome would need a web primitive inside the SwiftUI renderer, which is a new browser surface with cookie and session ownership. An SFSafariViewController hand-off changes the cookie/login store and history-back behaviour, so it needs product sign-off.

- DeviceSelectionPage (signed-out welcome): its presentation is a looping branded video (assets/images/onboarding.mp4) behind two lines of copy and one Get Started button that leads into the already-native onboarding. Reproducing it needs a looping-video primitive that no other screen needs, and dropping the video is a brand decision for design. Keep it in Flutter and revisit only if a video or hero primitive is justified elsewhere.

- QuickLook preview of chat composer attachments: Flutter has no such viewer, so this would be a new feature, not a migration. It adds system-side parsing of untrusted Office/PDF files and a share/export path, and needs product sign-off.

- Full viewers for historical non-image chat attachments and full-resolution historical chat images: the backend keeps no downloadable copy (non-image files go to OpenAI by file id; images keep only a 128px thumbnail), and Flutter has no viewer either. A viewer would need a new backend endpoint and download owner, which is outside presentation migration.

- Memories multi-select and global-search result multi-select: neither exists in Flutter (MemoriesProvider has no selection API and global_search.dart has none). Adding them would be new product features; the ledger wording is corrected instead.

- Training-data opt-in in the plans sheet: it is dormant behind const _showTrainingDataOptIn = false and intentionally forces the classic renderer. Keep it classic until the program is re-enabled so its consent renderer is not lost.

- CustomErrorWidget (the main.dart render-failure screen, including its 'error copied' SnackBar): the crash/render fallback path must never depend on the native bridge.

- Whisper confirmModelDownload dialog: only reachable on Android (iOS on-device transcription uses native speech), so there is no iOS presentation to migrate.

- Transcription JSON request/schema editor content above 262,144 UTF-16 units: by documented design it stays on the complete Flutter editor, reached automatically when a stored or imported configuration exceeds the cap; native import reads the clipboard uncapped in Dart. A chunked native document editor (UITextView with a delta and read protocol) is not justified for this edge case.

- Decorative, animation-only visuals with no functional content: device tutorial demo animations and glow, the scanning ripple, Wrapped story-style paging, card animations and pie painter, shimmer placeholders, the Stripe pulse ring, and brand SVG logos (Stripe, Omi hero pair). No illustration, story or video primitive is added. The native screens present the same data and actions with SF Symbols, bundled artwork thumbnails, progress rows and lists, and the animated versions remain in each screen's classic fallback.

- External and system UIs that are already native and owned elsewhere: Stripe onboarding in the external browser, Apple/Google Maps hand-off, the Intercom messenger, the sms: composer, the system share sheet, the StoreKit review sheet and the Shortcuts app.

- Interactive MapKit maps for the conversation map and recap journey: MapKit would fetch tiles for users' conversation locations from Apple, bypassing the backend's single-provider static-map seam, which is a privacy and provider change. Maps stay as Dart-fetched static images, with an explicit-tap MapsUtil hand-off.

- NativeHomeView recap-card map thumbnails: purely decorative, they would require a NativeHomeContract change, and the same data is reachable through the recap detail journey sheet.

- Default-build provider fixes found by the scouts are out of these batches because they change flag-off behaviour; batches fence at the presentation layer instead, and each needs its own review. They are: ActionItemsProvider.clearUserData not resetting _isSelectionMode; AddAppProvider.apiKeys not app-scoped and not cleared on sign-out; DevApiKeyProvider lacking session fencing; and createApiKeyServer logging the response body that contains the newly created secret.

## Critic addendum (authoritative)
- C7 validation traps: never let real-world data produce an invalid snapshot (which sends the whole screen to Flutter). Clamp numeric values into range, truncate labels with the provided helpers (chart labels ≤ 64, graph labels ≤ 256), and omit a control (show a label instead) when its inputs are degenerate (zero-duration recording, target ≤ 0, non-finite numbers, duplicate x values).
- C9: every showOmiSheet nativeBuilder fallback body must be wrapped in OmiSheetScaffold (see lib/pages/conversations/widgets/move_to_folder_sheet.dart:29-35).
- Native modal null semantics (P0): null from showIosNativeModal means "use the Flutter path"; cancel is a non-null result with action null. Every new caller must handle both.
- rich_text/message_ai links are honoured only when they are option ids of the row (P5); escape raw server text before Markdown parsing.
- Frozen cross-batch signatures (in addition to the list above): ConversationsPage(requestInitialLoad:, nativeLibrary:), conversationRowTitle, LiveCaptureCard.formatElapsed, DailySummaryDetailPage(summaryId:, summary:) + its {'deleted': true} pop result, MemoriesPage(asRoot:), ChatPage(isPivotBottom:, autoStartVoice:, initialDraft:), UsagePage(showUpgradeDialog:), showGlobalSearch(context, initialQuery:), HomeRecordButtonState.performPrimaryAction/showOptions, DeviceSettings(), ConnectDevicePage(), AutoSyncPage(), SyncPage().
- Frozen row ids checked by existing host tests: people 'person_<id>' + 'select'; owner_name, owner_save, developer_conversation:url, developer_save; offline_status_title, offline_download, offline_retry, offline_retention.
- Additional exclusions (stay Flutter): BootRecoveryApp (lib/startup/boot_recovery_app.dart) and StartupFailureApp (lib/startup_failure_app.dart) — crash/startup fallback paths must not depend on the native bridge.
- Use the P8 'level' row kind for labelled setting sliders; never reuse the playback 'slider'.

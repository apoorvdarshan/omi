## Spec
Extends the config-channel presenter. There is still exactly one active presentation, guaranteed by the P0 FIFO. Dart (ios_native_modal.dart): NativeModalResult gains final String reason, one of 'action', 'cancel' (explicit cancelId), 'dismissed' (swipe or scrim), 'programmatic', 'invalidated' (account-session change) or 'unmounted'. action stays null for every non-'action' reason, so existing callers are unaffected. A nil response from an older host maps to 'cancel'. showIosNativeModal gains Future<void>? dismissSignal: if it completes before a result, Dart invokes 'dismissPresentation'(id) and returns NativeModalResult(null, {}, reason: 'programmatic'). A native result that arrives after the signal is discarded, and a late signal is ignored. New Future<NativeActivity?> showIosNativeActivity(BuildContext context, {required String label}), label 1..200 chars. It returns null when unsupported, in which case the caller keeps its Flutter spinner dialog. Otherwise it returns a handle whose Future<void> dismiss() is idempotent. The handle also dismisses automatically on session change and when the caller context unmounts. Activities share the FIFO, so an alert requested during an activity waits for it. Swift (NativeModalPresenter.swift, AppDelegate.swift config handler): completion always returns {action: String?, values: {...}, reason: String}. The cancelId toolbar row gives 'cancel', presentationControllerDidDismiss gives 'dismissed' and dismiss(id:) gives 'programmatic'. New config method 'presentActivity' with {requestId, label, appearance, locale, direction}. It presents a UIHostingController(rootView: NativeActivityView) with modalPresentationStyle .overFullScreen, modalTransitionStyle .crossDissolve and isModalInPresentation true. The view has a dimmed background (black at 25%) and a centered card with ProgressView(label), using glassEffect on iOS 26+ and regularMaterial earlier. It adds accessibilityAddTraits(.isModal) and posts a UIAccessibility announcement of the label. It occupies the same active slot and finishes only through dismissPresentation (reason 'programmatic') or session invalidation. Validation: requestId is an Int >= 0; label is non-empty and at most 200 chars; appearance is system, light or dark; direction is ltr or rtl. The presenter rejects the request while another presentation is active.

## Required tests
Dart, native_presentation_test.dart with a mocked config channel: map every reason (action, cancel, dismissed, programmatic, invalidated, unmounted). A dismissSignal that fires before the result returns 'programmatic' and calls 'dismissPresentation' once; a result that arrives first wins and the late signal is ignored. A nil legacy response maps to cancel. The activity handle's dismiss is idempotent; a session-generation event dismisses it; unsupported returns null; an alert requested during an activity waits for it. Swift Preview: an 'activity' fixture shows the HUD, blocks taps to the content beneath and is dismissed programmatically. Fixtures for modal cancel and swipe report 'cancel' and 'dismissed'. The large-text activity label stays visible.

## Critic addendum (authoritative)
- Dismiss automatically when the caller's BuildContext unmounts — for modals as well as activities — reporting reason 'unmounted'.
- A dismissSignal that fires while the request is still waiting in the P0 FIFO drops it without presenting ('programmatic').
- The activity overlay is a UIKit full-screen presentation that would hide any Flutter route pushed beneath it: document that callers must dismiss the activity before awaiting any route/sheet, and enforce it defensively (e.g. presenting another native presentation or a Flutter route while an activity is up should dismiss the activity first, or the activity auto-dismisses after a maximum lifetime of 120 s with reason 'programmatic'). Pick one rule, implement and test it.
- State precisely which side reports 'invalidated' (session change, decided in Dart) versus 'programmatic' (Dart-requested dismissal).
- P0 implemented the FIFO as a head-of-line list with per-request tickets in ios_native_modal.dart: build dismissSignal and the activity overlay on its internal cancel hook (_PresentationTicket.leave()) and _inPresentationOrder. In widget tests do not await StreamSubscription.cancel() (it deadlocks fake-async); use unawaited.
- Also handle the Swift-side gap P0 reported: if UIKit fails to show a native modal or another owner dismisses it, NativeModalPresenter must release its active slot and complete with reason 'dismissed' (detect via presentationControllerDidDismiss / failed present / the presented controller disappearing).

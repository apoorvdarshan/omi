## Spec
Dart: NativeRow.valid allows blocks on kinds rich_text and message_ai (same RichBlock rules), forbids plainText together with blocks, and caps message_ai at 2,000 blocks; rich_text keeps its current limits. message_ai accepts null or an options key. Options are the link whitelist from nativeRichTextLinks of the same Markdown, and the Dart owner opens them through the existing launchUrl owner. New field String? chartStyle, 'line' or 'bar' (projection 'chartStyle'), valid only on kind chart. When set, points must have x = 0..n-1 in index order, finite y, label at most 64 chars, and 1 <= n <= 10,000. Swift: decoding mirrors this (blocks only on rich_text or message_ai; chartStyle only on chart with those two values). NativeSurfaceView.message(row): when blocks is non-empty, render NativeRichTextView(row:state:query: '') inside the bubble layout, keeping the frames preference used for visibility. For message_ai, its OpenURLAction discards any URL that is not an option id, even when options is empty (never .systemAction). Rows without blocks keep today's Text path and trailing-button behaviour. Rows with blocks show the trailing button only when row.symbol is set, so a link whitelist never adds a stray button. case chart: with chartStyle nil, the existing LineMark rendering is unchanged (Usage keeps it). With chartStyle set, render from 1 point, height 200. 'bar' draws BarMark(x: .value(subtitle, point.x), y: .value(title, point.y)). 'line' draws LineMark plus PointMark with .interpolationMethod(.catmullRom). .chartXAxis uses AxisMarks over the thinned x values (first, last and every ceil(n/6)th index) with AxisValueLabel showing that point's label. Add .accessibilityLabel(title).

## Required tests
Dart, native_chat_rendering_test.dart: message_ai with valid blocks is valid. plainText plus blocks is invalid, and 2,001 blocks are invalid. A link is accepted only when it is an options key. chartStyle is valid only on chart with line or bar. Non-index x, NaN y and a 65-char label are rejected. The Usage chart without chartStyle is unchanged. Swift contract: the same accept/reject matrix. Preview fixtures: 'chat-rich' renders a table, code, list and quote in an AI bubble; a non-whitelisted link is discarded and a whitelisted one sends its id; an AI row with blocks and no symbol shows no trailing button. 'chart-bar' and 'chart-line' cover long labels, a single point and large text.

## Critic addendum (authoritative)
- Link policy for ALL rich text (critic V4): NativeRichTextView currently returns .systemAction for rows with no options (NativeReaderComponents.swift ~22-27). Change it so that for every rich_text and message_ai row, a tapped URL is honoured ONLY if it is an option id of that row (sent to Dart); with empty options, links are discarded. Update existing rich_text producers if any relied on system handling (grep nativeRichText / nativeRichTextLinks callers) so links keep working through the Dart owner. Add Preview + Dart tests.
- Chart label length: provide a Dart helper (e.g. nativeChartLabel(String) truncating to 64 chars with an ellipsis) so producers truncate instead of making the whole surface invalid.

## Spec
Dart: new lib/mobile/native_ui/ios_native_feedback.dart with enum NativeToastKind {confirm, info, error, undo, progress} and enum NativeToastOutcome {action, closed, swiped, timeout, replaced, invalidated}. class NativeToastRequest has these fields: int requestId, strictly increasing per process; kind; message, 1..1000 graphemes with no U+0000; String? actionLabel, 1..40 graphemes, required for undo, allowed for error only when an onAction exists, null otherwise; String? closeLabel, error only; int durationMs, which must equal OmiFeedbackTiming for the kind (1500, 4000, 8000, 5000, 60000); String symbol, from an allowlist (checkmark.circle.fill, info.circle, exclamationmark.circle.fill, trash, person, tv, progress); double bottomClearance, finite and in 0..240; appearance (system, light or dark), locale and direction (ltr or rtl). It exposes Map projection and bool valid. Future<NativeToastOutcome?> showIosNativeToast(NativeToastRequest) invokes config 'toast' and completes when the toast ends. It returns null on MissingPluginException, an invalid request or FlutterError('invalid_native_toast'). Future<void> dismissIosNativeToast() invokes 'dismissToast'. NativeFeedbackHost.active is a synchronous bool that becomes true only after supportsIosSwiftUi() resolves true; set it inside supportsIosSwiftUi in ios_native_home.dart, which already requires iosSwiftUiEnabled && Platform.isIOS. The first toast subscribes to AuthService.sessionGenerationEvents and dismisses on any change. omi_feedback.dart: when NativeFeedbackHost.active, _show maps kind and icon (Icons.person* to person, Icons.tv* to tv, delete glyphs to trash, otherwise the kind default) and clearance (the existing _extraBottom(context)) into a request and fires it. If it gets null back, it shows today's SnackBar unchanged. undo() resolves true only for outcome action, after onUndo has run, and false for every other outcome, matching SnackBarClosedReason != action. error with onAction runs onAction on action. hide() also calls dismissIosNativeToast. A newer request completes the previous one with replaced. AppSnackbar needs no change because it delegates to OmiFeedback. ios_native_main_navigation.dart: while the native shell is mounted, it sets OmiFeedback.bottomClearance to 64 (the tab-bar reserve), plus the native Home footer height on the Home tab (a constant matched to NativeHomeView). It restores the previous closure on dispose, and the classic shell is untouched. Swift: NativeToastRequest is Decodable with validate() in NativeSurfaceContract.swift (Foundation only, so the Ruby contract test compiles it). New NativeToastPresenter.swift, @MainActor and owned by AppDelegate next to NativeModalPresenter, handles config methods 'toast' and 'dismissToast'. It keeps one PassthroughWindow per active UIWindowScene at windowLevel .normal + 1, above Flutter, platform views and presented sheets. hitTest returns nil outside the toast frame, and the window is hidden and released when idle. Its root is a UIHostingController(NativeToastView): a capsule with Image(systemName:) (or ProgressView for progress), Text(message).lineLimit(4), an optional accent action Button and an optional close Button(xmark) with accessibilityLabel(closeLabel). It uses glassEffect(.regular.interactive(), in: .capsule) on iOS 26+ and a regularMaterial capsule earlier. Bottom offset = max(keyboard overlap from UIKeyboard notifications, bottomClearance) + safeAreaInsets.bottom + 12. Outcomes: drag down past 24pt gives swiped, Task.sleep(duration) gives timeout, the action button gives action, the close button gives closed, a new request makes the previous one replaced, and dismissToast gives invalidated. On appear it posts a UIAccessibility announcement. With Reduce Motion it uses an opacity transition only. overrideUserInterfaceStyle and layoutDirection follow the request. Nothing is persisted or logged. Add NativeToastPresenter.swift to both Runner targets and the Preview project.

## Required tests
Dart, native_toast_test.dart: request validation covers kind/duration mismatch, an action on confirm, a missing undo label, close on undo, non-finite clearance and an over-long message. Outcome mapping: undo returns true only for action, and onUndo runs before resolution. replaced, timeout, swiped and invalidated all return false. error onAction runs exactly once. With NativeFeedbackHost.active false (flag off or Android), the config channel is never touched and the SnackBar path is byte-identical (existing ui_feedback tests stay green). A null result falls back to the SnackBar. A session-generation event dismisses. Swift contract test: rejects unknown kind, duration mismatch, action on confirm/info/progress, close on undo, non-finite or out-of-range clearance, and non-increasing requestId. Preview: a toast above a presented pageSheet is hittable; taps outside the toast reach the content below; VoiceOver announcement; RTL and accessibility text sizes; keyboard avoidance; swipe-down outcome.

## Critic addendum (authoritative)
- Request-id monotonicity must survive a Dart engine restart: do not make Swift reject a lower id permanently; instead scope ids per engine session (e.g. Swift resets its last id when it receives a request carrying a new per-process session token, or ignores ordering across sessions). The SnackBar fallback must never get stuck on.
- Exact icon mapping: only Icons.person_outline → person and Icons.tv_outlined → tv are used today (speaker_tag_prompt_card.dart); map trash for delete glyphs; everything else uses the kind default. List the mapping in code.
- Define behaviour while a P1 activity overlay is up: the toast window sits above it and stays tappable (Undo works).

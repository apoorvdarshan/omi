## Spec
Dart (ios_native_surface.dart): (a) class NativeSelection {const NativeSelection({required Set<String> selected, required Set<String> selectable, required NativeAction action}); projection {'selected': sorted list, 'selectable': sorted list}; bool validFor(Iterable<NativeSection>) is true when selectable has at most 10000 ids, every selectable id is a section row id and every selected id is selectable}. IosNativeSurface gains NativeSelection? selection and List<NativeRow> bottomBar (snapshot keys 'selection' and 'bottomBar'). dispatchNativeAction gains optional named NativeSelection? selection and Iterable<NativeSection> sections. id '_selection' with a List value whose elements are unique Strings, at most 10000, all selectable, calls selection.action(List<String>); owners treat it as the desired set and diff idempotently. bottomBar rows dispatch like toolbar rows. (b) bottomBar: at most 6 rows of kinds label (at most one), button and menu. Ids must be unique across toolbar, sections, bottomBar and chat/reader actions. Not allowed with chat, reader, navigation or a fill graph. (c) NativeSection gains NativeAction? reorder (projection 'reorderable': reorder != null) and bool collapsible (projection 'collapsible', requires a non-empty title). A reorderable section may contain only rows of kind task, navigation, label, toggle or menu. Command '_reorder:<sectionId>' takes a List value that must be an exact permutation of that section's current row ids (same length, unique, set-equal) and calls section.reorder(List<String>); anything else throws PlatformException('invalid_native_action'). Selection and reorderable sections are mutually exclusive. (d) NativeRow gains int? indent (0..3; kinds task, navigation, label, toggle, menu) and List<String> swipeLeading and swipeTrailing. Each swipe id must be in options.keys, with at most 3 per edge and no id on both edges; kinds task, navigation, menu. Dispatch is unchanged (value = option id), so every swipe action is also reachable from the context menu. (e) IosNativeSurface fills snapshot keys 'expandLabel' (l10n.expand) and 'collapseLabel' (l10n.collapseAction), the way it fills retry and loadingLabel. Swift (NativeSurfaceContract.swift, NativeSurfaceView.swift, and a new NativeListInteractions.swift added to both Runner targets and the Preview project): decode Selection {selected, selectable: [String]}; bottomBar: [NativeSurfaceRow]?, included in allRows; Section.reorderable and .collapsible: Bool?; Row.indent: Int?; Row.swipeLeading and .swipeTrailing: [String]?; expandLabel and collapseLabel: String?. Validation mirrors Dart exactly. replacingValue carries the new fields and withoutContent clears them. NativeModalPresenter rejects any of them. NativeSurfaceState gains optimisticSelection: Set<String>? and optimisticOrders: [String: [String]]. They apply immediately on user change and are dropped when a newer snapshot arrives while the command is not pending, or on failure. '_selection' and '_reorder:*' count as edits (latest value wins), and non-edit actions such as bottom-bar Delete wait for them, the way Save waits for text edits. Rendering applies in list mode only, never in reader or chat. Selection: List(selection: Binding(get: optimistic ?? selected, set: send the new set intersected with selectable, sorted, as '_selection')) with .environment(.editMode, .constant(.active)). Selectable rows render as static label(row) with no buttons, context menus or swipes. Other rows keep their control with .selectionDisabled(true) on iOS 17+; on iOS 16 they are disabled during selection and the setter filters them out. Reorderable sections: edit mode active, rows static, ForEach.onMove builds the full id permutation, applies it optimistically and sends '_reorder:<id>'; the system reorder controls provide VoiceOver drag. Collapsible: the header is a Button with chevron.down/chevron.up and the title, .isHeader trait and an accessibilityHint of expandLabel or collapseLabel. The collapsed set is view @State, cleared on invalidate, and rows are omitted while collapsed. Indent: .padding(.leading, indent * 20) with a 1.5pt quaternary Capsule rule when indent > 0. Swipes: .swipeActions(edge:, allowsFullSwipe: true) with buttons titled from options, role .destructive for 'delete', and systemImage from an allowlist (delete trash, complete checkmark.circle, reopen arrow.uturn.backward.circle, pin pin, unpin pin.slash, star star, unstar star.slash, review_right hand.thumbsup, review_wrong hand.thumbsdown, otherwise none). Swipes are suppressed while selecting or reordering. bottomBar: .safeAreaInset(edge: .bottom) { NativeGlassControls { ViewThatFits(in: .horizontal) { HStack(label, Spacer, buttons); VStack(label, buttons) } }.padding(12).background(.bar) }, with buttons from rowView(compact: true).modifier(NativeGlassButtonStyle()), destructive role, and disabled when !enabled or pending. Inside the native shell it sits above the separate tab-bar surface.

## Required tests
Dart, native_list_interactions_test.dart: validFor (selectable not a subset of rows, selected not a subset of selectable, more than 10000). '_selection' rejects non-list values, non-strings, duplicates and unknown ids, and passes a List<String> through. bottomBar limits on kinds, count, labels and id uniqueness, plus the chat/reader/fill-graph conflicts. '_reorder' rejects duplicates, missing, extra, foreign and stale ids and accepts an exact permutation. Selection plus reorder falls back. indent bounds and kinds. Swipe ids must be a subset of options, edges disjoint, at most 3 per edge. collapsible requires a title. Swift contract: accept and reject for each new field. Preview fixtures: 'selection' (edit-mode circles; tap toggles optimistically; the sorted set is sent; a non-selectable Show more row stays usable on iOS 17; bottom-bar Delete waits for the pending selection; large text keeps the bottom bar reachable), 'reorder' (drag sends the full permutation; a failure reverts to the snapshot order), 'collapsible' (rows hidden, VoiceOver hint), 'swipe' (sends the option id; no swipe while selecting), 'indent' (rule visible, row height unchanged).

## Critic addendum (authoritative)
- NativeSurfaceState.update (NativeSurfaceView.swift ~line 36-37) filters queued edit values and failedEdits to current row ids or '_search'. Extend that filter so queued '_selection' and '_reorder:<sectionId>' values (for sections that still exist) are not dropped on every snapshot. Test it.
- Selection lifecycle: document that owners must exit selection mode when their route pops or is disposed (the library batch will call ConversationProvider.exitSelectionMode); the primitive itself clears optimistic selection on invalidate.
- P0 left integration_test/support/native_host_harness.dart's nativeProjectedRow without bottomBar (the field did not exist). P4 owns adding bottomBar rows to that lookup (you may edit that harness file for this only).

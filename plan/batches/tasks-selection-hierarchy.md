## Instructions
Common rules: Dart only (no shared bridge, Swift, l10n or docs edits). ActionItemsProvider stays read-only and the sole mutation owner. Flag-off behaviour is unchanged; any invalid row falls back to the complete Flutter Tasks page. Uses P0, P2 and P4 (selection, bottomBar, reorder, indent, collapsible, swipe). 1) Behaviour-preserving extraction into the new task_hierarchy.dart, all pure and unit-tested: orderedTaskItems (from _getOrderedItems), visibleDescendantIds, maxIndentForDrop, maxIndentFor(item, ordered) (the _showTaskMenu indent rule: indent allowed only while indentLevel < min(previous indent + 1, 3)), and defaultDueDateForCategory(category, now) (from _getDefaultDueDateForCategory). The page uses them. From _TaskSelectionActionBarState, extract confirmAndDeleteSelectedTasks(context, provider) (showOmiConfirm deleteTasksTitle(n), deleteSelectedItems, rollback and bulkDeleteFailed) and exportSelectedTasks(context, provider) (connected integration first; none gives OmiFeedback.error with a Connect action to TaskIntegrationsPage; already-exported items skipped; progress, success and partial feedback; exits selection). The Flutter bar calls them. 2) Add bool selectionBarInFallback = false to ActionItemsPage. When true, the classic Stack includes Positioned(bottom: 0, TaskSelectionActionBar()). In home/page.dart, change only the native-shell 'tasks' builder to ActionItemsPage(key: _actionItemsPageKey, selectionBarInFallback: true) and stop mounting the bar outside it. The classic path is untouched. 3) Remove 'if (provider.isSelectionMode) return classic'. In selection mode: title selectedCount(n). Toolbar: 'tasks_cancel' (xmark) calling endSelection; 'tasks_select_all' titled selectAllTasksMenu, or deselectAllTasksMenu when everything is selected, calling selectAllItems or clearSelection. Rows are kind 'label' (symbol checkmark.circle or circle for completion, indent = indentLevel, the same subtitle) inside the same sections. NativeSelection: selectable = all visible task row ids, selected = mapped selectedItems. The action diffs: each added id gets selectItem plus selectItem for every visibleDescendantIds; each removed id gets deselectItem plus its descendants (the same semantics as toggleItemSelection with cascadeIds). bottomBar: a count label; 'tasks_delete' (trash, destructive, n > 0) calling confirmAndDeleteSelectedTasks; 'tasks_export' (title exportButton + ' · ' + n, square.and.arrow.up, n > 0) calling exportSelectedTasks. Outside selection, the toolbar menu 'selectAll' also shows deselectAllTasksMenu when everything is selected. 4) Normal rows: kind 'task' (checkbox toggles completion, tap opens) with indent = item.indentLevel and subtitle = due date · goal title · exportedToPlatform(platform). Options: open; select; indent (indentTask) when indentLevel < maxIndentFor; outdent (outdentTask) when > 0; 'due' (l10n.setDueDate), which opens showOmiRowMenu (title setDueDate, one action per other TaskCategory title) and runs the existing _updateTaskCategory with the same dates as drag-and-drop; complete (markComplete or markIncomplete); delete. swipeLeading is ['complete'] (calls _toggleCompleted); swipeTrailing is ['delete'] (calls deleteTaskWithUndo). 5) Sections: title is the category title, footer is tasksCountLabel(n). Overdue and No deadline are collapsible. When showCompletedView, add a destructive 'tasks_clear_<category>' (tasksClearCompleted) calling _confirmClearCompleted. While searching with no matches, empty is noResultsFound; for an empty list show a label section with tasksEmptyStateMessage. Keep the typed API status as failed. 6) Reorder: page-local bool _nativeReorderMode. The toolbar menu gains 'reorder' (l10n.edit) only when not searching and not selecting. In reorder mode the toolbar shows 'tasks_reorder_done' (l10n.done, checkmark), and each category section gets reorder: ids. Validate an exact permutation of the current row ids, otherwise throw PlatformException. Then call batchUpdateSortOrders({id: (i + 1) * 1000}). For the moved item, compute maxIndentForDrop on the new order and call updateItemIndentLevel when the current indent exceeds it (the same clamp as a drop with dx 0). Moves between categories go through 'due', and indent changes through the menu (no horizontal drag). Reorder is disabled while searching or selecting. 7) Keep goal titles via _getGoalTitleForTask and the native load-more row. No new strings.
